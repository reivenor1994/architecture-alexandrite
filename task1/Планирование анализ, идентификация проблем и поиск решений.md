# Задание 1. Анализ, идентификация проблем и решений, планирование

## 1. Проблемные места

### 1.1. Проблемы с производительностью
- **MES API долго грузит список заказов** (дашборд с фильтрами и пагинацией не помогает)
- **Расчет стоимости заказа занимает 2–30 минут** (зависит от сложности 3D-модели)
- **RabbitMQ** (возможное узкое место при высокой нагрузке, интеграция CRM API ↔ MES API)

### 1.2. Проблемы с обработкой заказов
- **Потеря заказов** (жалобы клиентов и API-пользователей)
- **Нет четкого механизма приоритизации заказов** (операторы берут новые заказы, старые "зависают")
- **Нет уведомлений клиентов** (статусы заказов не отслеживаются)

### 1.3. Данные
- **Потенциальная рассинхронизация статусов** (Статусы заказов меняются в разных системах, нет механизма компенсирующих действий при сбоях)
- **Долгий расчет стоимости из-за файлов с 3D-моделями** (нет оптимизации обработки, долгий расчет цены)

### 1.4. Процессы
- **Ручное тестирование задерживает релизы** (QA находит критические баги перед продакшеном)
- **Нет автоматического мониторинга** (проблемы обнаруживаются только по жалобам)
- **Сервисы имеют по одному инстансу** (нет отказоустойчивости)
- **Нет возможности отследить путь заказа в системе** (нельзя понять где именно оборвалась цепочка вызовов)

## 2. Инициативы для решения проблем

### 2.1. Оптимизация производительности
- **Ввести кеширование в MES API** (кешировать список заказов, чтобы дашборд грузился быстрее)
- **Вынести расчет стоимости в отдельный микросервис** (масштабируемость при росте нагрузки)
- **Оптимизировать RabbitMQ** (настроить кластеризацию, мониторинг очередей)

### 2.2. Улучшение обработки заказов
- **Добавить систему очередей заказов** (приоритизация и гарантированная доставка в MES)
- **Логирование статусов в ELK** (единый трекинг заказов)
- **Добавить уведомления для клиентов** (email, sms и push-уведомления при изменении статуса)

### 2.3. Улучшение работы с данными
- **SAGA-паттерн для управления статусами** (Координация между CRM API и MES API через события, компенсирующие транзакции при ошибках)
- **Оптимизировать хранение 3D-файлов** (сжатие, предварительная обработка)

### 2.4. Автоматизация и мониторинг
- **Внедрить автотесты** (QA не будет задерживать релизы)
- **Настроить логирование и алерты** (ELK + Grafana для мониторинга)
- **Перейти на Kubernetes** (масштабируемость, отказоустойчивость)
- **Настроить трейсинг** (возможность выявить причины медленной работы сервисов)

### 3. Приоритеты на полгода

### Целевая архитектура через полгода
- **MES API и CRM API работают быстро** (кеширование, оптимизация очередей)
- **Заказы не теряются** (надежная синхронизация статусов)
- **Есть мониторинг и алерты** (ELK, Grafana)
- **CI/CD автоматизирован** (меньше задержек с релизами)

### Топ-3 инициативы:
- **Кеширование в MES API** 
  - Даст мгновенный эффект для операторов
- **Гарантированная доставка заказов** 
  - Устранит главную боль клиентов
- **Автотесты**
  - Сократит задержки релизов
