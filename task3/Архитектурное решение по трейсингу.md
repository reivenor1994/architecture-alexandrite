Проблемное место: 
  - долгий расчет стоимости, зависание заказов

### Список данных, которые должны попадать в трейсинг

- Order ID (Уникальный идентификатор заказа)
- Timestamp (Время события)
- Service (Сервис, в котором произошло событие)
- Status (Текущий статус заказа)
- User ID (Идентификатор пользователя)
- File ID (Идентификатор 3D-файла)
- Calculation time (Время расчета стоимости)
- Error details (Детали ошибки)
- Queue time (Время в очереди RabbitMQ)
- Worker ID (Идентификатор оператора)

## 2. Мотивация

Возможности, которые предоставляет трейсинг:

- **Прозрачность процесса** - визуализация цепочки вызовов через все системы.
- **Быстрая диагностика** - определение точного места и причины проблем.
- **Снижение времени простоя** - оперативное реагирование на возникающие инциденты.
- **Анализ узких мест** - выявление систем, требующих оптимизации.

Внедрение трейсинга даст компании:

- **Снижение количества жалоб клиентов** - позволит оперативно выявлять и устранять "зависшие" заказы до того, как клиенты начнут жаловаться.
- **Скорость диагностики проблем** - разработчики смогут быстро находить, в каком именно сервисе произошла ошибка.
- **Прозрачность процессов для бизнеса** - Менеджеры и операторы смогут видеть реальное время выполнения каждого этапа заказа. Позволит выявлять узкие места (например, долгий расчет стоимости).
- **Снижение потерь из-за "потерянных" заказов** - трейсинг поможет выявлять заказы, которые "зависли" между сервисами.
- **Обоснование для масштабирования** - данные трейсинга покажут, какие сервисы чаще всего становятся узким местом

Ожидаемые улучшения от внедрения трейсинга:

**Технические**:
  - **Время диагностики проблем сократится на 70%**
  - **Количество "потерянных" заказов уменьшится на 90%**
  - **Среднее время обработки заказа снизится на 20%**

**Бизнес-метрики**:
  - **Удовлетворенность клиентов увеличится на 30%**
  - **Количество жалоб уменьшится на 50%**
  - **Среднее время выполнения заказа сократится на 15%**

## 3. Предлагаемое решение

**Технологический стек**:

- **Jaeger Collector** - прием трейсов от сервисов
- **Jaeger Storage** - хранение трейсов

**Автоматический мониторинг**:

- **Интеграция OpenTelemetry** 

  - Внедрить OpenTelemetry в сервисы Shop API, CRM API и MES API для сбора трассировок
  - Настроить экспорт трейсов в Jaeger Collector

- **Настройка Jaeger**

  - Использовать Jaeger Storage для хранения и анализа трейсов
  - Настроить Jaeger UI для просмотра цепочек вызовов и выявления узких мест

- **Алертинг на основе трейсов**

  - Метрики для алертинга
    - Время выполнения заказа (например, > 30 минут для PRICE_CALCULATED)
    - Заказы без изменения статуса (> 7 дней)
    - Ошибки в цепочке вызовов (HTTP 500, тайм-ауты)
  - Инструменты:
    - Prometheus + Alertmanager для настройки алертов на основе метрик из Jaeger
    - Grafana для визуализации метрик и дашбордов

- **Автоматические действия**

  - Отправка уведомлений для оперативного реагирования

## 4. Компромиссы

Ограничения при внедрении трейсинга:

**Производительность**:
  - **Трейсинг добавит ~5-10% нагрузки на сервисы**
  - **Для высоконагруженных эндпоинтов потребуется выборочное включение трейсинга**

**Сложные интеграции**:
  - **RabbitMQ потребует дополнительных усилий для передачи context propagation**
  - **Устаревшие клиенты API могут не поддерживать заголовки трейсинга**

**Стоимость**:
  - **Хранение полных трейсов более 7 дней экономически нецелесообразно**
  - **Для 3D-файлов будет собираться только метаинформация (не содержимое)**

**Не покрываются**:
  - **Действия пользователей внутри UI**

## 5. Аспекты безопасности

Меры защиты:

1. **Контроль доступа к данным трейсов**:
- Внедрение ролевой модели:
  - `support-read` — только просмотр трейсов
  - `devops-full` — доступ к расширенным данным + API
  - `audit-admin` — управление настройками хранения
  
Снижает риск внутренних угроз, например, утечка данных сотрудником.

2. **Защита передачи данных**:
  - Маскирование конфиденциальных данных (номера карт и т.д.)
  - Шифрование трейсов при передаче и хранении
  - Запрет на логирование файлов 3D-моделей (только метаданные)

Даже при утечке трейсов злоумышленник не получит личных данных клиента

3. **Аудит**:
  - Логирование всех запросов к данным трейсинга
  - Регулярные проверки доступа

Помогает расследовать инциденты, например, подозрительные действия сотрудника
