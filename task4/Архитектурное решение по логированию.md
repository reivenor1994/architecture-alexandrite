# Задание 4. Логирование

## 1. Анализ

Для эффективного логирования необходимо собирать информацию из следующих систем:

**Internet Shop**:

- Запись времени начала запроса к API (для последующего сопоставления с серверными логами, помогает оценить задержку сети) (INFO) - только в dev-режиме
- Предупреждения о нестандартном поведении UI (WARN)

**CRM**:

- Запись времени начала запроса к API (для последующего сопоставления с серверными логами, помогает оценить задержку сети) (INFO) - только в dev-режиме
- Предупреждения о нестандартном поведении UI (WARN)

**MES**:

- Запись времени начала запроса к API (для последующего сопоставления с серверными логами, помогает оценить задержку сети) (INFO) - только в dev-режиме
- Предупреждения о нестандартном поведении UI (WARN)

**Shop API**:

- Создание заказа (INFO)
- Изменение статуса заказа (INFO)
- Ошибки валидации (ERROR)
- Критические ошибки (ERROR)

**CRM API**:

- Изменение статусов (INFO)
- Действия продавцов (INFO)
- Ошибки бизнес-логики (ERROR)

**MES API**:

- Изменение статусов (INFO)
- Расчет стоимости (INFO)
- Действия операторов (INFO)
- Долгие расчеты (WARN)
- Критические сбои (ERROR)

## 2. Мотивация

**Технические преимущества**:

- Сокращение времени на диагностику проблем и их выявление до жалоб клиентов
- Улучшение мониторинга интеграций между системами
- Сбор данных для анализа производительности

**Бизнес преимущества**:

- Снижение количества жалоб клиентов
- Улучшение прозрачности процессов для клиентов
- Снижение потерь от невыполненных заказов

### Приоритеты внедрения

1. MES API и MES - как наиболее проблемные компоненты с точки зрения производительности и жалоб операторов
2. Shop API и Internet Shop - для отслеживания проблем клиентов при создании заказов
3. CRM и CRM API - для мониторинга процессов подтверждения заказов

## 3. Предлагаемое решение

**Технологический стек**:

- **ELK (Elasticsearch, Logstash, Kibana)** - для сбора, обработки, хранения и анализа логов
- **Alertmanager** - для уведомлений о критических ошибках, аномальном времени ответа, увеличении числа ошибок

**Компоненты**:

- **Logstash** - Сбор и обработка логов из различных источников
- **Elasticsearch** - Хранение и индексация логов
- **Kibana** - Визуализация и анализ логов
- **Alertmanager** - Обработка алертов и отправка уведомлений

**Политика безопасности**:

1. Чувствительные данные:
   - Маскировка персональных данных
   - Шифрование логов при передаче и хранении
   - Отдельные индексы для чувствительных логов
2. Доступ:
   - Разделение прав доступа по ролям
   - Аудит доступа к логам
   - Двухфакторная аутентификация для доступа к Kibana

**Политика хранения**:

1. Индексы:
   -  Создать отдельные индексы для каждой системы и типа логов

2. Категории логов и сроки хранения:
   - Логи безопасности: (Содержат информацию об аутентификации, авторизации, доступе к данным, изменениях конфигурации безопасности) - 1 год
   - Бизнес-логи: (Содержат информацию о бизнес-событиях, таких, как создание заказов, изменение статусов заказов, взаимодействие с клиентами) - 3 месяца
   - Логи производительности: (Содержат информацию о времени ответа системы, использовании ресурсов, времени выполнения запросов) - 6 месяцев
     Логи отладки: (Содержат детализированную информацию о работе системы, используемую для отладки и локализации проблем) - 1 неделя

3. Размер:
   - Определить максимальный размер индексов для каждой системы
   - Использовать ротацию индексов для автоматического удаления старых данных

## 4. Необходимые мероприятия

**Алертинг**:

- Резкий рост ошибок (>10% от общего числа запросов)
- Долгие расчеты стоимости (>15 минут)
- Потеря сообщений между системами
- Аномальное количество заказов

**Поиск аномалий**:

- Статистический анализ частоты событий
- Корреляция логов разных систем

**Автоматизация**:

- Автоматические отчеты по ключевым метрикам
